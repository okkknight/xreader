# XReader 用户端“编辑阅读空间”重构规格

## 1. 范围与目标

本次只重构用户端三页：

- 首页 `/`
- 归档页 `/archive`
- 文章阅读页 `/articles/[slug]`

后台管理、数据库结构、Fish Audio 接入、课程内容生产和音频生成不在本次范围内。

目标是让用户在安静、连续的阅读空间里完成一篇课程：知道今天读什么，能快速开始，播放时知道当前段落和下一步，并且在桌面端和移动端都不被播放器或课程信息遮挡。

## 2. 设计方向

采用“安静的知识杂志”方向：

- 开放版式优先，减少无必要的卡片、阴影、徽章和装饰。
- 保留衬线字体的文章阅读气质，使用墨绿色作为主要交互强调色。
- 页面以白色或极浅纸张色为背景，底部播放器使用深墨绿色形成稳定的阅读边界。
- 正文是文章页的视觉中心；课程路线和播放器服务于正文，不与正文竞争。
- 不使用悬浮字幕框。当前英文句子只在正文中高亮，播放器内部只显示一行当前播放信息。

## 3. 页面一：首页

### 页面作用

让用户在首屏理解“今天读什么”和“如何开始”。首页只突出今日文章，不展示后台状态、统计面板或多余推荐。

### 复用关系

- 复用 `AppShell` 的品牌和主导航。
- 复用文章摘要视图模型，但不直接复用旧版大卡片布局。
- 复用本地进度存储返回的进行中状态；没有进度时显示开始状态。

### 组件清单

- `SiteHeader`：固定品牌与 Today、Archive 导航。
- `TodayIntro`：固定文案“把英文读进一段安静的时间里。”。
- `TodayArticleFeature`：今日文章的主题、难度、标题、中文标题、导语、预计阅读/讲解时长和进度。
- `ArticleStartActions`：开始讲解、先读文章两个入口。
- `ProgressLabel`：由本地进度派生的“未开始 / 继续上次进度 / 已完成”。

### 布局说明

桌面端使用左侧大标题、右侧今日文章信息的开放式两列结构；不使用包围整个区域的卡片。文章信息以顶部细线和留白分组。主按钮靠近文章标题，次入口为低强调文字按钮。

移动端改为单列：品牌导航、页面标题、今日文章、操作按钮依次排列；文章卡不超过屏幕宽度，不出现横向滚动。

### 组件说明与来源

- 文章标题、中文标题、主题、难度、导语：后端 `PublicArticle` 数据。
- 预计时长：后端文章/课程派生字段；若缺失，不显示伪造时长。
- 进度状态：`localStorage` 中该文章的 guided/reading 进度，属于本地派生状态。
- 按钮文案：固定中文文案。

### 交互流程与状态流转

- 点击“开始讲解”：进入文章页，模式为 `GUIDED`，从保存的 guided 段落继续；无保存位置时从第一段开始。
- 点击“先读文章”：进入文章页，模式为 `READING`，从保存的 reading 句子继续；无保存位置时从第一句开始。
- 文章不存在：保留明确的空状态，不显示“后台准备”等内部措辞。

## 4. 页面二：归档页

### 页面作用

让用户快速浏览已发布课程并继续过去的阅读，不承担推荐、筛选和后台编辑功能。

### 复用关系

- 复用 `SiteHeader`。
- 复用 `ArticleListItem`，但不复用首页的首屏文章布局。
- 复用 `ProgressLabel` 和 `localStorage` 进度派生逻辑。

### 组件清单

- `ArchiveIntro`：页面标题“往期阅读”和一句简短固定说明。
- `ArticleList`：按发布时间倒序排列的文章列表。
- `ArticleListItem`：日期、主题、难度、标题、导语、进度和进入链接。
- `ArchiveEmptyState`：无文章时的公开用户文案。

### 布局说明

桌面端采用两列开放式列表，每一项以细线分隔，避免重复的大卡片。标题使用衬线字体，元信息使用无衬线小字。移动端变为单列，列表项之间保留足够留白。

### 组件说明与来源

- 日期、标题、主题、难度、导语：后端 `PublicArticle`。
- 完成状态：本地进度派生状态。
- 入口 URL：文章 slug 生成的稳定链接。

### 交互流程与状态流转

- 点击列表项任意可点击区域：进入对应文章页，恢复该模式的本地位置。
- 当前有进度：列表项显示继续状态，但不显示精确的伪造百分比；若后端提供可靠总数，再显示真实进度。
- 无文章：显示“还没有已发布的文章。”，不暴露后台工作流。

## 5. 页面三：文章阅读页

### 页面作用

承载完整的听读流程：文章正文、讲解路线、播放控制和阅读辅助工具必须有清晰层级，且不遮挡正文。

### 复用关系

- 复用 `SiteHeader`，但文章页顶部保留足够留白，不增加复杂工具栏。
- 保留现有 `playbackReducer`、`AudioController`、`buildGuidedQueue`、`buildReadingQueue` 和进度存储。
- 将当前 `ArticleReader` 拆成编排组件和独立区域组件；播放状态仍由一个页面级状态源管理。

### 组件清单

- `ReaderHeader`：返回入口、主题/难度、英文标题、中文标题、导语、模式切换。
- `ReaderToolbar`：显示中文、自动跟随和讲解字幕等轻量设置；只显示已支持的功能。
- `ArticleCanvas`：段落、句子、句子高亮、翻译和释义标注。
- `LessonOutline`：课程路线、段落类型、顺序、当前状态和当前段详情。
- `LessonOutlineItem`：单个课程段，默认只展示短标签和状态，不展示长讲稿。
- `CurrentLessonDetail`：当前教师讲解的可展开文本，位于课程路线内部，不悬浮在播放器上方。
- `ReaderPlayerDock`：底部播放器，包含上一段、播放/暂停、下一段、当前类型、位置、倍速。
- `ResumeFollowButton`：用户主动滚动后显示的“回到当前讲解”。

### 布局说明

桌面端：

1. 顶部为文章标题与模式切换。
2. 中间为两列：左侧正文阅读区，右侧课程路线。
3. 右侧课程路线使用 sticky 定位，当前段详情在路线内部展开。
4. 底部为固定播放器 dock，页面正文底部预留播放器高度。

移动端：

1. 顶部只保留标题、模式切换和必要工具。
2. 正文单列，句子点击区域保持足够触控高度。
3. 课程路线折叠为“课程路线”入口，打开后使用底部抽屉或内联展开区，不覆盖正文核心内容。
4. 播放器固定在底部，播放器只显示控制和一行当前状态；不得在播放器上方再次出现字幕浮层。

### 组件说明与来源

- 标题、正文和句子：后端 `PublicArticle`。
- 课程路线：后端 `lessonSegments`，按 `order` 排序。
- 当前句子：播放队列和 `activeItemId` 派生状态。
- 当前段类型和位置：当前播放队列项和队列索引派生状态。
- 当前教师脚本：当前 `LessonSegment.script`，只在 `CurrentLessonDetail` 展开时显示。
- 高亮：当前播放项的 `sentenceIds` 与正文句子 ID 的交集。
- 翻译显示：本地 UI 状态；翻译字段缺失时不显示空行。
- 自动跟随：本地 UI 状态；用户手动滚动后暂停，点击恢复按钮后重新开启。
- 播放完成：播放器状态和本地进度派生状态。

### 交互流程与状态流转

- 点击模式切换：保留当前文章位置，映射到目标模式的最近队列项，并停止旧音频后从目标项继续。
- 点击正文句子：设置当前句子并播放覆盖该句子的队列项。
- 播放器上一段/下一段：只操作当前模式队列，更新句子高亮、课程路线当前项和进度。
- 点击课程路线项：跳转到该段第一句并播放；当前项显示选中状态。
- 用户手动滚动：播放不中断，但自动跟随暂停；显示“回到当前讲解”。
- 点击“回到当前讲解”：恢复自动跟随并将当前句子滚动到安全视口。
- 点击显示中文：仅展开已有翻译，不影响播放队列。
- 点击讲解详情：展开当前段脚本；切换段落时收起旧详情，避免长文本堆叠。
- 播放完成：播放器显示完成状态，正文保留最后高亮但不增加遮挡层。
- 音频缺失或播放失败：播放器停止并显示可理解的错误提示；不让页面进入假播放状态。

## 6. 样式与组件边界

### 视觉 tokens

- `--ink`：深墨绿色正文和播放器背景。
- `--green`：主要交互色和当前状态色。
- `--muted`：辅助信息和未选中状态。
- `--line`：细分隔线。
- `--paper`：极浅纸张背景；不使用明显渐变。
- 间距使用有限的 4/8/12/20/32/48/72 级别，避免页面各处随意设置。

### 文件边界

- `src/components/ui/site-header.tsx`
- `src/components/home/today-article-feature.tsx`
- `src/components/archive/article-list.tsx`
- `src/components/reader/reader-header.tsx`
- `src/components/reader/article-canvas.tsx`
- `src/components/reader/lesson-outline.tsx`
- `src/components/player/reader-player-dock.tsx`
- `src/styles/tokens.css`
- `src/styles/shell.css`
- `src/styles/home.css`
- `src/styles/archive.css`
- `src/styles/reader.css`
- `src/styles/player.css`

现有播放逻辑文件不因视觉重构而合并进页面组件。旧组件只在没有消费者时删除；数据服务和后台组件不改名、不迁移。

## 7. 实现顺序

1. 建立 tokens、Shell 和新的 Header。
2. 先完成文章页桌面端一条完整听读路径：标题、正文、课程路线、底部播放器。
3. 在浏览器中校准第一视口和播放状态，再补移动端布局。
4. 重构首页与归档页，共用新的公开文章摘要视图模型。
5. 接通模式切换、课程路线跳转、恢复跟随、翻译和播放完成状态。
6. 删除旧悬浮字幕与不再使用的样式，运行单元测试、E2E 和浏览器视觉验收。

## 8. 验收标准

- 首页首屏能在 5 秒内理解今日文章和两个开始入口。
- 归档页不再表现为首页卡片的重复堆叠。
- 文章页正文是主视觉，右侧路线和底部播放器有明确层级。
- 播放过程中，当前句子、路线当前项、播放器状态保持一致。
- 播放栏上方没有重复字幕或悬浮白框。
- 桌面端正文不被右侧路线或底部播放器遮挡。
- 移动端无横向溢出，路线展开不遮挡当前阅读句子。
- 模式切换、句子点击、上一段、下一段、倍速、翻译、恢复进度和完成状态继续可用。
- `npm run lint`、`npm test`、课程音频校验和浏览器视觉检查通过。

## 9. 明确不做

- 不实现后台管理功能。
- 不新增登录、账号、收藏、搜索、评论或推荐系统。
- 不改课程内容、讲解脚本、Fish Audio reference_id 或音频文件。
- 不在本次重构中加入复杂动画、弹窗体系或多层设置面板。
