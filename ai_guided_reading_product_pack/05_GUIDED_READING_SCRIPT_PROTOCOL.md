# AI 带读讲稿协议

## 1. 讲稿目标

讲稿不是文章翻译，也不是语法讲义。

讲稿要帮助用户完成：

- 知道文章在回答什么
- 跟得上文章如何推进
- 理解真正困难或重要的位置
- 注意少量高价值表达
- 在听觉上获得连续、自然、有人陪伴的阅读体验

## 2. 基本单位

基本单位不是单句，而是：

> 语义块 + 教学目标

一个语义块可以包含 1–3 句。

## 3. 片段类型

### `OPENING`

自然开场，20–35 秒。

任务：

- 从问题或现象切入
- 激发好奇
- 给一个轻量阅读方向

禁止：

- 罗列学习目标
- 预告全部词汇
- 过度欢迎
- 固定“大家好，欢迎来到……”

### `ORIENTATION`

建立文章地图，15–30 秒。

任务：

- 告诉用户文章大致如何展开
- 不提前说完答案
- 提醒一个阅读关注点

### `ARTICLE_READ`

播放原文语义块。

字段：

- 句子 ID
- 原文音频
- 对应高亮
- 是否首次播放

### `QUICK_EXPLANATION`

快速确认，8–20 秒。

适用：

- 简单事实
- 次要背景
- 只需要确认段落功能

### `NORMAL_EXPLANATION`

一个主要重点，20–45 秒。

适用：

- 一个表达
- 一个逻辑关系
- 一个中等难句
- 一处作者语气

### `DEEP_EXPLANATION`

核心位置，40–90 秒。

适用：

- 全文中心句
- 关键转折
- 容易严重误解的复杂句
- 值得迁移的核心表达

数量：每篇 3–4 个。

### `EXPRESSION_NOTE`

讲一个高价值表达，15–35 秒。

结构：

1. 此处含义
2. 为什么值得注意
3. 一个自然例句
4. 回到文章

不要讲词源、同义词大全和多组例句。

### `CONTEXT_CONNECTION`

连接前后文，8–20 秒。

例如：

- 回扣开头问题
- 指出段落功能变化
- 预告下一步论证
- 对比前后语气

### `REPLAY`

重播原句或语义块。

适用：

- 英文节奏好
- 对比需要重新听
- 深讲后值得再次整体理解

### `SECTION_SUMMARY`

阶段性收束，15–30 秒。

不必每段都有。文章中间最多 1–2 次。

### `FINAL_WRAP`

全文收束，35–60 秒。

任务：

- 回答文章核心问题
- 梳理文章结构
- 点出 2–3 个最值得保留的语言观察
- 自然结束

不做测验，不要求复述。

## 4. 标准播放结构

示意：

```text
OPENING
ORIENTATION
ARTICLE_READ: block 1
QUICK_EXPLANATION
CONTEXT_CONNECTION
ARTICLE_READ: block 2
NORMAL_EXPLANATION
ARTICLE_READ: block 3
DEEP_EXPLANATION
REPLAY
CONTEXT_CONNECTION
...
FINAL_WRAP
```

不要求每篇完全相同。

## 5. 讲解决策规则

对每个语义块评估三个维度，每项 1–5：

- `comprehensionDifficulty`
- `articleImportance`
- `teachingValue`

参考决策：

- 总分 3–5：`SKIP` 或并入朗读
- 总分 6–8：`QUICK`
- 总分 9–11：`NORMAL`
- 总分 12–15：`DEEP`

分数只是辅助。核心句即使语言简单，也可以深讲其文章作用。

## 6. 单次讲解规则

每个讲解片段只能有一个主目标。

错误：

> 同时解释三个词、一个语法、作者态度和背景知识。

正确：

> 只解释这一句中的对比为何是全文中心。

其他内容延后或删除。

## 7. 词汇讲解标准

值得讲的表达：

- 影响理解
- 在多种场景中可迁移
- 中文直译容易错
- 体现作者态度
- 是文章主题表达的关键

不值得讲：

- 只因为是生词
- 专有名词
- 用户可以从上下文直接猜到
- 低频且对文章理解不重要
- 为了凑数量

老师可以明确说：

> “这个词知道此处意思就够了，不必单独记。”

## 8. 长难句讲解

推荐顺序：

1. 先说整句在文章里做什么
2. 给出核心意思
3. 找主干
4. 只拆真正造成困难的部分
5. 重新合起来
6. 必要时重播原句

不要从语法标签开始。

错误：

> “这是一个由 which 引导的非限制性定语从句……”

更好：

> “先抓住主干：研究并没有证明这个方法有效。中间的 `which...` 只是补充研究采用了什么条件。”

必要时再补术语。

## 9. 文章逻辑讲解

老师应优先解释：

- 作者从现象进入解释
- 例子支持什么
- 转折改变了什么
- 结论比前文更谨慎还是更强
- 某段是证据、限制还是应用

这比孤立语法更能提升整篇理解。

## 10. 听觉写作规则

讲稿是给耳朵听的，不是给眼睛看的。

要求：

- 中文句子尽量短
- 长句拆成两到三句
- 英文例句前后留出自然提示
- 不连续朗读多个括号内容
- 数字、缩写和专有名词提前做发音处理
- 同一段不要连续出现过多英文
- 片段结尾要自然，不依赖屏幕标点才能理解

## 11. 片段结构

```json
{
  "id": "seg_008",
  "order": 8,
  "type": "DEEP_EXPLANATION",
  "sentenceIds": ["p03s01", "p03s02"],
  "primaryGoal": "Explain the article's central contrast.",
  "script": "这一句是全文的关键……",
  "voiceRole": "teacher",
  "highlightMode": "sentence_range",
  "autoScrollTarget": "p03s01",
  "pauseBeforeMs": 300,
  "pauseAfterMs": 600,
  "replaySourceSegmentId": null
}
```

## 12. 全局一致性

生成完整讲稿时维护：

- `expressionsAlreadyTaught`
- `ideasAlreadyExplained`
- `previousParagraphFunction`
- `openQuestionFromOpening`
- `teacherToneState`
- `estimatedDuration`

禁止重复解释同一个概念，除非明确回扣。

## 13. 时长控制

建议：

- 开场与定位：45–60 秒
- 文章原文播放：3–5 分钟
- 快讲：合计 1–2 分钟
- 普通与深讲：合计 4–6 分钟
- 收束：35–60 秒
- 总时长：8–12 分钟

先控制信息密度，再控制字数。

## 14. 讲稿失败模式

- 每句都讲
- 每段都以“我们来看”开头
- 全文变成中文翻译
- 任何词都称为地道表达
- 深讲点过多
- 不记得前文
- 口头禅密集
- 例句太多
- 长篇背景科普
- 假装有个人经历
- 结尾重复整篇翻译
